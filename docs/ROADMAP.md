# 今後の機能・改善の候補

オーロラ壁紙チェンジャー（Aurora Wallpaper Changer）に今後追加・改善するとよい機能の一覧。2026-10-10 時点のコードと、脆弱性・問題点の見直し（S1～S3、B1～B8）の結果をもとにまとめた。

優先度の目安:

- **高**: 既存の利用者が困る場面がある、または開発の事故を防ぐもの
- **中**: あると便利で、既存の仕組みの延長で作れるもの
- **低**: 要望が出てから検討すればよいもの

対応済みの項目は見出しの優先度を【完了】に変え、経緯が分かるよう内容は残す。一部だけ対応した項目は優先度の後に「一部完了」と付け、残りの作業を書く。実装しないことにした項目は【見送り】に変え、理由を書く。

## 2. 使い勝手の改善

### 壁紙の履歴を再起動後も残す【完了】

- **状況**: 2026-10-24 に完了（29a6623）。
- **内容**: 「前の壁紙」の履歴と、順送りの位置をファイルに保存する。
- **理由**: 履歴はメモリにしか無く、再起動すると「前へ」で戻れるのは起動時の壁紙だけになる。分割表示の順送りは、再起動のたびに先頭から始まる（起動時の壁紙が合成画像で、候補の一覧に無いため）。
- **実装**:
  - モニターごとの履歴（画像の組の一覧と、表示中の位置）を `%LOCALAPPDATA%\WallpaperChanger\history.json` に保存する（`IWallpaperHistoryStore` / `JsonWallpaperHistoryStore`）。頻繁に書くため、設定ファイルとは分けた
  - `WallpaperRotationService` が最初の切り替えのときに読み込み、切り替えで履歴が変わるたびに保存する。一部のモニターで失敗した場合やキャンセルされた場合も、それまでに変わった分は保存する
  - 順送りは履歴の最後の組の続きから選ぶため、保存した履歴があれば再起動後も続きから進む。解像度の変更で合成し直すときも、保存した組を使う
  - 読めない・壊れている履歴ファイルは無視し、次の保存で置き換える（設定ファイルと違って退避はしない）。表示できない組（レイアウトと画像の枚数が合わないもの）は、復元するときに除く
  - 保存した履歴があるモニターでは、起動時の壁紙を履歴に記録しない。そのため、アプリを起動していない間に Windows の設定で変えた壁紙には「前へ」で戻れない

### 「この画像を表示しない」と「画像の場所を開く」【完了】

- **状況**: 2026-10-24 に完了（575e65a）。
- **内容**: トレイのメニューに次の 2 つを追加する。
  - 今表示している画像を除外リストに入れる
  - 今表示している画像をエクスプローラーで選択した状態で開く
- **理由**: 気に入らない画像を外すには、今はフォルダから移動・削除するしかない。分割表示では、どのファイルが表示されているかも分からない。
- **実装**:
  - トレイのメニューに「この画像を表示しない」「画像の場所を開く」を追加した。表示中の画像は、メニューを開くたびに `IWallpaperRotationService.GetCurrentWallpapersAsync`（履歴の現在位置）から取り直す。起動直後でも、保存した履歴から分かる
  - モニターが複数なら「1. モニター名: ファイル名」の項目にし、分割表示のモニターは子メニューにマスを並べる（「左上: ファイル名」、16 分割は「2 行 3 列: ファイル名」）。モニターが 1 台なら、モニターの階層は省く
  - 表示しない画像は `AppSettings.ExcludedImages`（全モニター共通）に保存する。`IImageProvider` ではなく `WallpaperRotationService` が候補から外し、「前へ」や解像度の変更で合成し直すときも、表示しない画像を含む組は使わない
  - 指定した直後に `ReplaceExcludedImagesAsync` で、その画像を表示しているマスだけを選び直す（1 枚表示なら別の画像になる）。選び直せる画像が無ければ、今の表示を残して理由を通知する
  - 設定画面に「表示しない画像」の一覧を追加し、「表示に戻す」「場所を開く」をできるようにした
  - 「場所を開く」は `explorer.exe /select,"パス"`。ファイルが無い場合は、エクスプローラーを開かずに通知する
  - 順送りで、今の画像がどれも候補に無い場合（表示しない画像にした・削除したなど）は、先頭に戻らず、パス順でその画像の次から選ぶようにした

### モニターをつなぎ替えても設定を引き継ぐ【完了】

- **状況**: 2026-10-24 に完了（7678476）。
- **内容**: 接続先のポートを変えたモニターや買い替えたモニターに、それまでの設定を引き継げるようにする。
- **理由**: 設定は IDesktopWallpaper のデバイスパスをキーにしている。パスにはポートごとの識別子が含まれるため、ケーブルを別のポートに挿すと別のモニターとして扱われ、設定が無い状態になる。
- **実装**:
  - デバイスパス（`\\?\DISPLAY#GSM7666#5&14b0cd61&0&UID4355#{...}`）の 2 つ目の要素が EDID のメーカー ID と製品コードになっているため、これを型番として使う（`MonitorHardwareId`）。EDID の API を呼ばずに済み、接続していないモニターの設定（保存済みのパス）からも型番が分かる。EDID を読めないモニターの `Default_Monitor` は型番として扱わない
  - 自動の引き継ぎ（`MonitorSettingsInheritor`）: 壁紙フォルダを設定していない接続中のモニターに、同じ型番の接続していないモニターの設定が 1 つだけあれば、その設定と履歴を移す。同じ型番のモニターが複数あって対応が決まらないときは引き継がない
  - 引き継ぎは、モニター構成の監視を始めるとき（アプリを起動していない間に接続先を変えた場合）と、モニターが接続されたとき（壁紙を表示する前）に行う
  - 設定はコピーせずに移す。コピーすると同じ型番の設定が増え、次に接続先を変えたときに引き継ぎ元が決まらなくなるため。そのため、同じ型番のモニターを場所ごとに使い分けている場合は、設定が共通になる
  - 手動のコピー: 設定画面に「ほかのモニターの設定をコピー」を追加した。買い替えて型番が変わったモニターや、自動で引き継げなかった場合に使う。コピー元には接続していないモニターも並べる
  - 接続していないモニターを設定画面で示せるよう、モニターの名前を設定に記録する（`MonitorSettings.DisplayName`）
  - あわせて、計算用のプロパティ（`UsesTileFolders`）が設定ファイルに保存されていたのを直した

### 起動直後にエクスプローラーが応答しない場合の再試行【完了】

- **状況**: 2026-10-24 に完了（b8f6f86）。
- **内容**: 起動時のモニター取得が時間切れになっても終了せず、しばらく待って再試行する。
- **理由**: B2 の対応で、COM の呼び出しは 30 秒で時間切れになるようになった。サインイン直後の自動起動でエクスプローラーの準備が間に合わないと、今は起動に失敗して終了する。
- **実装**:
  - `ApplicationHostedService.StartAsync` で、モニター構成の監視（`IMonitorConfigurationWatcher.StartAsync`）の完了を待たずに起動処理を進める。始められなければ、10 秒、20 秒、40 秒…と待ち時間を倍にしながら（上限 5 分）、始められるまで再試行する
  - 時間切れ（`TimeoutException`）に限らず、どの失敗でも再試行する（エクスプローラーの準備中は COM のエラーになることもあるため）。監視を始められない間も、壁紙の自動切り替えは続く（切り替えのたびにモニターを取得し直すため）
  - 監視を待つ間も、フォルダ未登録のときの設定画面の表示と、2 つ目に起動されたときの要求の受け付けは進める
  - 再試行中に終了するときは、応答しないエクスプローラーの呼び出しを待たずに終了する
  - トレイアイコンは、もともと監視を始める前に表示している

### 「今すぐ変更」でフォルダを数え直す【完了】

- **状況**: トレイの「全壁紙を更新」で一部完了（2026-10-21、e5fb7df）。2026-10-24 に設定画面にも同じ操作を用意して完了（9a4e495）。
- **内容**: 手動の切り替えでは、列挙結果のキャッシュを使わずにフォルダを数え直す。
- **理由**: B3 の対応で列挙結果をキャッシュするようになった。変更を監視できないネットワーク共有では、追加した画像が最長 10 分間候補に入らない。
- **実装**:
  - `IWallpaperRotationService.RefreshAsync` を追加した。`IImageProvider.Invalidate()` でキャッシュを捨て、「前の壁紙」で戻った後の進む履歴も辿らずに選び直す
  - `IWallpaperScheduler.RefreshNowAsync`（自動切り替えの待ち時間もリセットする）を、トレイの「全壁紙を更新」から呼ぶ
  - トレイの「次の壁紙」は、キャッシュを使う軽い切り替えとして残した（数え直したいときは「全壁紙を更新」を使う）
  - 設定画面の「今すぐ全モニターを変更」を「全壁紙を更新」に置き換え、`RefreshNowAsync` を呼ぶようにした。同じ働きのボタンが 2 つ並ばないよう、ボタンは足さずに置き換えた。モニターごとの「次の壁紙」は、トレイの「次の壁紙」と同じく、キャッシュを使う軽い切り替えのまま
  - 定期実行では数え直さない（今のまま）

### 1 枚表示での写真の向き（EXIF）の確認【完了】

- **状況**: 2026-10-24 に実機で確認し、変更不要とした（3ec2b37）。
- **内容**: 縦向きに撮った写真を 1 枚表示にしたとき、Windows が向きを補正するかを実機で確かめる。補正しない場合は、補正した画像を作って設定する。
- **理由**: B5 の対応では、分割表示とプレビューだけを補正した。1 枚表示は画像を OS にそのまま渡している。
- **確認の結果**:
  - 画素を横倒しにして EXIF の Orientation = 6（時計回りに 90° 回して表示）を書き込んだ確認用の画像を壁紙に設定したところ、Windows が向きを補正して正しい向きで表示した（Windows 11 Pro 10.0.26300）
  - そのため、1 枚表示は今のまま画像を OS にそのまま渡す。Windows 10 では確かめていない（横倒しになるという報告があれば、向きの指定がある画像だけ回転済みのコピーを作って設定する。画面に合わせて切り抜くと Windows の「調整方法」が効かなくなるため、元の大きさのまま回転だけする）

## 3. 表示の拡張

### 1 枚表示の表示方法（拡大・全体表示・中央など）【完了】

- **状況**: 2026-11-07 に完了（a76d3e9）。
- **内容**: モニターごとに、Windows の「調整方法」に当たる設定を選べるようにする。
- **理由**: 今は Windows 側の設定のままで、アプリからは変えられない。縦長の写真を全体表示したい場合などに困る。
- **実装**:
  - 設定画面の壁紙フォルダ欄に、1 枚表示のときだけ「表示方法」の選択欄を追加した。選べるのは「Windows の設定に従う」（既定）「画面を埋める」「全体を表示」「引き伸ばす」「中央に表示」。Windows の「並べて表示」と「スパン」は除いた（スパンは「複数モニターにまたがる 1 枚表示」で扱う）
  - 設定は `MonitorSettings.SingleImageFit`（`ImageFit?`、null は Windows の設定に従う）に保存する。既存の設定は null になるため、今までどおり画像をそのまま渡す。ほかのモニターの設定のコピーにも含まれる
  - `IDesktopWallpaper.SetPosition` は全モニター共通のため使わず、表示方法を指定したモニターでは、分割表示と同じ `WicWallpaperComposer` でモニターの解像度の画像を作って設定する（`WallpaperCompositionRequest.Fit`、1 列 1 行）。画像を覆わない余白は黒で塗る（分割表示の空きマスの色の設定は使わない）。拡大縮小・切り抜き・配置の計算は `TileLayout.CalculatePlacement` にまとめた
  - 合成するため、撮影時の向き（EXIF）の補正と、画像の大きさの上限（`ImageSourceLimits`）も分割表示と同じく効く
  - 表示方法を変えると、今の画像を新しい表示方法ですぐに表示し直す（`ReapplyAsync`）。「前の壁紙」で戻るときも、今の表示方法で作る（履歴には表示方法を残さない）
  - 解像度が変わったときは、表示方法を指定したモニターだけ作り直す。Windows の設定に戻したときは、作った画像を表示しているモニターだけ元の画像を設定し直す

### 分割表示の間隔・背景色・マスへの収め方を画面で設定する【完了】

- **状況**: 2026-11-07 に完了（351d6e2）。
- **内容**: マスの間隔と、間隔・空きマスの色を設定画面で変えられるようにする。あわせて、マスに画像を収める方法として「全体を表示（余白あり）」も選べるようにする。
- **理由**:
  - 間隔と色の設定（`WallpaperCompositionOptions.TileGap` / `BackgroundColor` / `EmptyTileColor`）は、コード上にはあるが画面に出していない
  - 今は常に「マスを覆うように拡大して中央を切り抜く」ので、写真の端が切れる
- **実装**:
  - 設定画面の壁紙フォルダ欄に、分割表示のときだけ「マスへの収め方」（マスを埋める / 全体を表示）、「間隔」（0～32 px のスライダー）、「間隔の色」「空きマス・余白の色」（黒・濃い灰色・灰色・薄い灰色・白から選ぶ）を追加した。変えると、今の画像の組のまま表示し直す（`ReapplyAsync`）。間隔のスライダーは、動かしている間に何度も合成し直さないよう、止めてから 0.5 秒後に反映する
  - 設定はモニターごと（表示レイアウトと同じ）に `MonitorSettings.TileStyle`（`TileStyle`: `Fit` / `Gap` / `GapColor` / `EmptyColor`）として保存する。既定値は今までと同じ（マスを埋める、4 px、濃い灰色 0x202020、黒）。ほかのモニターの設定のコピーにも含まれる
  - 設定ファイルのソース生成による読み込みでは、ファイルに無い init プロパティが初期値ではなく 0 になる。そのため 4 つの値を `MonitorSettings` に直接置かず、1 つのオブジェクトにまとめた。この設定を追加する前の設定ファイルでは null になるので、`Normalize` で既定値に置き換える（間隔 0・黒の間隔に変わってしまうのを防ぐ）。範囲外の間隔・色・収め方も `Normalize` で補正する
  - 間隔と色は、`WallpaperCompositionOptions` から外し、`WallpaperCompositionRequest`（`Gap` / `GapColor` / `EmptyColor`）で渡すようにした。1 枚表示の表示方法で作る画像は、間隔なし・余白は黒のまま
  - 用意した色に無い色（設定ファイルを直接書き換えた場合など）は、「#RRGGBB」として選択肢の末尾に加えて表示する
  - 空きマスの色を変えられるようになったため、画面の「黒で表示」などの文言を「空きマス」に改めた

### 複数モニターにまたがる 1 枚表示（スパン）【完了】

- **状況**: 2026-11-07 に完了（8b6e637）。
- **内容**: 1 枚の画像を、すべてのモニターにまたがって表示する。
- **実装**:
  - モニターごとの設定というアプリの作りに合わせ、全モニターで一括にはせず、表示レイアウトに「スパン」を追加した（`WallpaperLayout.Span`）。スパンを選んだ接続中のモニターどうしで 1 枚の画像を分け合い、ほかのモニターは今までどおり個別に切り替わる（ノート PC の画面だけ外す、など）
  - 画像の取得元は、スパン専用のフォルダを 1 組だけ持つ（`AppSettings.Span`: フォルダ・サブフォルダの検索・選び方・収め方）。パノラマ写真を集めたフォルダなどを想定している。モニター自身のフォルダはそのまま残るので、スパンをやめれば元に戻る。設定画面では、スパンを選んだモニターのフォルダ欄・サブフォルダ・ランダム設定がスパンの設定を編集する
  - 収め方は「モニター全体を埋める」と「全体を表示（余白は黒）」から選ぶ
  - Windows の「スパン」は全モニター共通の設定のため使わず、スパンに参加するモニターの外接矩形（`MonitorInfo.Bounds`）に画像を収めてから、各モニターの位置で切り分け、モニターごとの画像として設定する（`SpanLayout.Calculate`、`IWallpaperComposer.ComposeSpanAsync`）。拡大する場合は、外接矩形の大きさに拡大してから切り分けるとメモリを使いすぎるため、元の大きさでデコードし、切り分けてから拡大する。モニターの縁の幅は考慮しない
  - 切り替え（`WallpaperRotationService`）では、スパンのモニターが 1 台でも対象に含まれていれば、接続中のスパンのモニターをまとめて 1 回で処理する。そのため、設定画面やトレイで 1 台の「次の壁紙」「前の壁紙」を押しても、スパン全体が変わる
  - 履歴はスパン全体で 1 つ持ち、モニターの履歴と同じファイルに `*span*` というキーで保存する。表示中の画像（トレイの「この画像を表示しない」「画像の場所を開く」）は、スパンのモニターごとに同じ画像を 1 項目で示す
  - モニター構成の監視（`MonitorConfigurationWatcher`）では、スパンのモニターの接続・切断・解像度の変更と、モニターの配置の変更で、今の画像のままスパンを作り直す。接続されたスパンのモニターには「次の壁紙」を表示しない（ほかのスパンのモニターの画像が変わらないように）
  - 設定画面でスパンに加えたときは今のスパンの画像のまま作り直し、スパンから外したときは残りのスパンのモニターも作り直す
  - スパンに参加するモニターは、自身のフォルダが無くても設定済みとして扱う（接続先を変えたときの引き継ぎで、スパンの設定が上書きされないように）

## 4. 自動切り替えの拡張

### 全画面アプリの実行中・バッテリー駆動時は切り替えない【完了】

- **状況**: 2026-11-08 に完了（a5fa9c7）。
- **内容**: ゲームや動画の全画面表示中、プレゼンテーション中、バッテリー駆動中は、自動切り替えを止める（設定で選べるようにする）。
- **理由**: 分割表示の合成は CPU とディスクを使う。全画面アプリの最中に処理が走ると、カクつきの原因になり得る。
- **実装**:
  - 設定画面の「切替設定」に「全画面表示のアプリの実行中は切り替えない」「バッテリーで動作しているときは切り替えない」を追加した（`AppSettings.SkipConditions`、全モニター共通）。どちらも既定で有効にした（Windows のスライドショーも、既定ではバッテリー駆動中に止まるため）。この設定を追加する前の設定ファイルでも既定値になるよう、2 つを 1 つのオブジェクトにまとめ、ファイルに無ければ `Normalize` で既定値にする
  - 止めるのは定期実行（`WallpaperScheduler`）だけで、「次の壁紙」などの手動の切り替えと、モニターの接続時の切り替えは止めない
  - 切り替えの時刻に条件に当てはまれば、その回を飛ばすのではなく、1 分ごとに調べ直して待ち、当てはまらなくなったらすぐに切り替える（間隔が長いと、飛ばした場合に次の切り替えまで長く待つため）。待った後は、その切り替えから 1 間隔待つ（待っている間に過ぎた時刻の分を続けて切り替えない）。待っている間に一時停止したときは切り替えず、「次の壁紙」を押したときは待つのをやめる
  - 全画面かどうかは `SHQueryUserNotificationState` の Busy（全画面のアプリ）、RunningD3DFullScreen（Direct3D の排他的な全画面）、PresentationMode（プレゼンテーション モード）で判定する。画面のロック中・スクリーンセーバーの表示中・集中モードは含めない
  - 電源は `GetSystemPowerStatus` の ACLineStatus が 0（バッテリー）のときだけバッテリー駆動とみなす（不明・バッテリーの無い PC では止めない）。`SystemEvents.PowerModeChanged` は使わず、待っている間は 1 分ごとに調べ直す（全画面の終わりは通知が無いため、同じ方法にそろえた）
  - 待っている間は、設定画面の切替設定とトレイのアイコンのツールチップに理由を表示する（`IWallpaperScheduler.Hold`）
  - Windows の API の呼び出しは `ISystemStateProvider`（`WindowsSystemStateProvider`）にまとめ、テストでは差し替える

## 5. 配布に向けて（配布を始めるとき）

### Microsoft Store（MSIX）で配布する【配布時に高】

- **状況**: 2026-11-08 に、配布の方法を Microsoft Store に決めた（元は「インストーラーと自動更新」。Velopack・Inno Setup・MSIX を候補にしていた）。Partner Center の開発者アカウントはある。
  - 2026-11-08 に、StoreReleaseKit（Store で配るアプリで表示をそろえるための手順とひな形）に従い、アプリ名を「オーロラ壁紙チェンジャー」（英語名「Aurora Wallpaper Changer」。どちらもストアで予約済み）、バージョンを 1.0.0 にして、設定画面に「アプリの情報」（「このアプリについて」「ライセンス情報」）を置き、ライセンス表示（`WallpaperChanger.UI/ThirdPartyNotices.txt`、`tools/notices/build-notices.sh`）とプライバシーポリシー（`docs/PrivacyPolicy.md`）、リリースの作業（`docs/BuildGuide.md`）を加えた
  - 残りは、README の英語版と日本語版を分けること（StoreReleaseKit の決まり）、パッケージで動くときの保存先と自動起動の切り替え、パッケージの作成と提出
- **内容**: 単一ファイル発行をやめ、MSIX パッケージにして Microsoft Store で配る。インストール・更新・アンインストールは Store が行うため、自動更新の仕組みは自分で作らない。
- **理由**:
  - 単一ファイル発行では、ネイティブ DLL が一時フォルダに展開される（S3、現状維持で保留中）
  - zip で配ると、一時フォルダやダウンロードフォルダから実行されやすく、自動起動の登録が壊れやすい（S2）
  - Store で配る MSIX は、審査の後に Microsoft が署名し直すため、コード署名の証明書が要らない。Store に MSI・EXE のインストーラーを出す方法もあるが、その場合は署名と更新の仕組みを自分で用意する必要がある
- **実装の手がかり**（パッケージで動くときだけ切り替え、パッケージ無しで動くときの動きは変えない）:
  - **AppData の仮想化**: MSIX で動くデスクトップアプリが `%LOCALAPPDATA%` に新しく作るファイルは、パッケージ専用の場所に振り替えられ、ほかのプロセスからは見えない（[Understanding how packaged desktop apps run on Windows](https://learn.microsoft.com/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)）。合成画像（`Composites`）のパスをそのまま `IDesktopWallpaper` に渡すと、壁紙を描くエクスプローラーが画像を読めず、分割表示・スパン・表示方法で作った壁紙が表示されない恐れがある。「ログフォルダを開く」も空のフォルダを開くことになる。パッケージで動くときは、ほかのプロセスからも見える実際のフォルダ（`ApplicationData.Current.LocalFolder`、`%LOCALAPPDATA%\Packages\<パッケージ ファミリ名>\LocalState`）に保存する。設定・履歴はアプリの中だけで使うため振り替えのままでもよいが、保存先はそろえる
  - **自動起動**: HKCU への書き込みも振り替えられるため、Run キーでは自動起動できない。マニフェストの `windows.startupTask` 拡張と `Windows.ApplicationModel.StartupTask` に変える（`IStartupRegistrationService` の実装を差し替える）。ユーザーがタスク マネージャーや Windows の設定で無効にした場合（`DisabledByUser`）は、アプリから有効に戻せないため、設定画面で Windows の設定から有効にするよう案内する
  - **パッケージの作成**: 発行プロファイル（`WallpaperChanger.UI/Properties/PublishProfiles/win-x64.pubxml`）の `PublishSingleFile` と `IncludeNativeLibrariesForSelfExtract` を外す。パッケージのマニフェスト（`Package.appxmanifest`。`runFullTrust`、`windows.startupTask`、表示名は日本語「オーロラ壁紙チェンジャー」と英語「Aurora Wallpaper Changer」）と、各サイズのロゴ画像（`tools/IconGenerator` で作る）を用意する。パッケージは Visual Studio の「Windows アプリケーション パッケージ プロジェクト」（`.wapproj`）か、Windows SDK の `makeappx` で作る
  - **確認**: 作ったパッケージをこの PC にインストールし（開発用の自己署名で）、壁紙（1 枚表示・分割表示・スパン）、自動起動、ログ、設定の保存を確かめてから提出する
  - **Store への提出**: アプリ名の予約、説明文とスクリーンショット（日本語と英語）、年齢区分、価格を用意する。プライバシーポリシーが求められるかは提出のときに確認する

### 多言語化【完了】

- **状況**: 2026-11-08 に完了（6e29de2）。
- **内容**: 画面・通知の文言を英語などにも切り替えられるようにする。
- **理由**: 文言は日本語でコードに直接書いている（リソースファイルが無い）。
- **実装**:
  - 対応する言語は日本語（既定）と英語。設定画面の「起動・言語・ログ」の「表示言語（Language）」で選ぶ（`AppSettings.Language`）。見出しには両方の言語を書き、選択肢はその言語自身の名前（日本語 / English）にして、今の言語が読めなくても見つけられるようにした
  - 言語の変更は、アプリの再起動後に反映する。画面の文言は作るときに取り出すため、その場で切り替えるには開いている画面やメニューをすべて作り直す必要があり、手間に見合わないため。変更したときは、変更した先の言語で再起動を案内する
  - 文言は `WallpaperChanger.UI/Resources/Strings.resx`（日本語）と `Strings.en.resx`（英語）に移した。ビルド時に厳密に型指定されたクラス（`Strings`）を生成し、C# からは `Strings.Xxx`、XAML からは `{x:Static res:Strings.Xxx}` で参照する。値を埋め込む文言は `Localizer.Format` で書式設定する
  - WPF は XAML をコンパイルするために一時プロジェクトで先に C# をコンパイルするが、リソースのクラスは通常その後で生成される。そのため `WallpaperChanger.UI.csproj` に、コンパイルの前に生成させるターゲット（`GenerateStringsBeforeCompile`）を加えた
  - Infrastructure で作る、画面に出る文言（例外のメッセージ・モニターの名前「内蔵ディスプレイ」など）も、`WallpaperChanger.Infrastructure/Resources/Strings.resx` に移した。Core の文言はログと開発者向けの例外だけのため、移していない
  - 言語は、設定を読み込んだ直後、画面を作る前に反映する（`Localizer.Apply`）。どのスレッドで作る文言も同じ言語になるよう、スレッドのカルチャに任せず、リソースのクラスのカルチャを明示する。設定を読み込むまで（設定ファイルが壊れていた場合の通知を含む）は、Windows の表示言語にかかわらず日本語にする
  - ログは調査用のため、言語にかかわらず日本語のまま書く
  - テストは日本語の文言で確かめるため、すべてのテストの前に表示言語を日本語にする（`DisplayLanguageFixture`。CI の実行環境は英語のため）。すべての文言に英語があり、埋め込む値の番号が日本語とそろっていることもテストで確かめる（`LocalizationTests`）
  - 英語でも収まるよう、4 分割のマスの一覧の幅を広げた（Bottom right が切れていたため）
